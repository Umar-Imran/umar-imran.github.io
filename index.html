01 / PERFORMANCE

Enterprise HR platform

Enterprise reporting: hours to seconds.

My role · Reporting optimization and full-stack delivery

Problem. Large-tenant reports took hours to generate, making routine HR reporting slow to use.

My contribution. I replaced ORM-heavy data access with targeted SQL and improved the reporting path while preserving configurable fields and company-scoped data.

Outcome: report generation fell from hours to seconds for the large-tenant reporting workloads I worked on.

Technical decisions and validation

The reporting system selects columns and joins for the requested fields, scopes queries by company, and separates data retrieval from export formatting. Its regression scenarios cover historical field values and date-sensitive reports.

The trade-off: faster SQL paths also need careful validation of permissions, historical data and edge cases. The result above describes the reporting improvement, not a benchmark for every report.

02 / PRODUCT

Multi-tenant planning SaaS

Interactive planning across UI, APIs and data.

My role · Full-stack feature development

Problem. Scheduling work across teams requires a responsive planning interface backed by consistent, permission-aware data.

My contribution. I developed canvas-based planning interactions, including drag-and-drop scheduling, inline editing and optimistic GraphQL updates, alongside background workflows for calendars, notifications and billing.

Outcome: teams can edit plans directly on the scheduling surface, with changes connected to the product’s persistent data and downstream workflows.

Technical decisions and trade-offs

The React/Konva grid renders visible rows and columns. Relay connects the interface to GraphQL; authenticated request context is passed to PostgreSQL for row-level access policies. Background jobs handle work outside the interactive request.

The trade-off: immediate UI feedback must be reconciled with server results, while rendering fewer cells must preserve the user’s position and interactions. These are system characteristics; they do not imply sole authorship of the platform.

03 / INTEGRATIONS

CRM and Microsoft 365

Bidirectional CRM–Outlook synchronization.

My role · Architecture, implementation and production delivery

Problem. Contact changes need to move between systems without creating update loops or bypassing user permissions.

My contribution. I built the bidirectional integration and Office add-in, including webhook processing, permission-aware mapping, OAuth token handling, queues and operational visibility.

Outcome: a production integration that synchronizes contact changes between CRM and Outlook, skips unchanged records and exposes background-job status for troubleshooting.

Reliability, security and testing

The sync service compares contact data before writing back to prevent repeated updates. Workers use rate limits and record job events; token storage is encrypted. Permission, webhook and analytics tests cover selected behavior around the integration.

The trade-off: background synchronization is asynchronous. Permission checks, retries and failure visibility are part of the product experience rather than assumptions about immediate delivery.
